1. 프로젝트 개요
------------------------------------------------------------
- 프로젝트명: Picklog (인스타그램 장소 아카이빙 서비스)
- 역할: 백엔드 API 서버
- 기술 스택: FastAPI + SQLAlchemy 2.x + PostgreSQL(PostGIS) + Playwright
- 배포: Railway (API) + Supabase (DB)


2. 인프라 구성 (완료)
------------------------------------------------------------

  - Docker Compose: PostgreSQL 15 + PostGIS 3.3, Redis
  - Poetry 기반 의존성 관리 (Python >=3.14)
  - Alembic 마이그레이션 관리

[클라우드 배포]

    - Swagger UI: https://capstone2be-production.up.railway.app/docs


3. DB 스키마 (완료 - 13개 테이블)
------------------------------------------------------------
  instagram_crawl_jobs    - 비동기 크롤링 잡 상태/결과 (id, status, source, payload, error)
  users              - 사용자 (email, password, kakao_id, nickname, profile_image)
  storages           - 저장소/창고 (title, description, is_public, deleted_at)
  storage_members    - 저장소 멤버 (storage_id, user_id, role: owner/editor/viewer)
  places             - 장소 마스터 (name, address, coordinate(PostGIS POINT), category_group, phone, homepage_url)
  place_raw_data     - 1차 raw 데이터 (provider, provider_place_id, raw_payload(JSONB), place_id 'nullable'). 인스타 raw도 여기 통합
  place_reviews      - 장소 리뷰 (네이버 블로그 등 외부 출처)
  place_images       - 장소 이미지 (image_url, source, is_representative)
  spots              - 스팟 (storage_id, place_id, added_by, instagram_url, caption, user_memo, user_rating, is_visited)
  place_space_dna    - 장소 공간DNA (mbti_axes(JSONB), ai_summary)
  tags               - 태그 마스터 (name)
  place_tags         - 장소-태그 연결 (place_id, tag_id, score)
  user_space_dna     - 유저 공간DNA (mbti_axes(JSONB), preferred_vibe_tags, total_visits)
  user_space_dna_history - 유저 DNA 변화 이력 (spot_id, mbti_axes_snapshot)

핵심 설계 패턴:
  - StorageMember 다대다 관계로 공유 창고 지원 (owner/editor/viewer 역할)
  - Place-first 정규화: 장소 정보를 Place에 중앙 관리, Spot은 개인 저장 기록
  - 소프트 삭제: storages.deleted_at, spots.deleted_at
  - GeoAlchemy2 POINT + GIST 인덱스 (idx_places_coordinate 자동 생성)


4. 구현된 API 엔드포인트 (완료)
------------------------------------------------------------
[인증 - /auth]
  POST /auth/register       회원가입 (기본 저장소 자동 생성)
  POST /auth/login          로그인 (OAuth2 form data, JWT 발급)
  POST /auth/kakao          카카오 OAuth 로그인 (모바일 SDK access_token → JWT)

[사용자 - /users]
  GET  /users/me            내 정보 조회
  PUT  /users/me            프로필 수정 (nickname, profile_image)
  GET  /users/me/space-dna  내 공간 DNA 조회 (없으면 has_data=false)
  GET  /users/me/pins?storage_ids=&visited=&bbox=  지도 마커용 슬림 응답 (다중 storage 합치기, viewport bbox·visited 필터, 1000건 캡 + X-Truncated 헤더)
  GET  /users/search?q=&size=  닉네임 prefix 검색 (창고 초대용. 본인 제외, 카카오 임시 이메일 우회)

[저장소 - /storages]
  GET    /storages                   내 저장소 목록 (페이징: page, size)
  POST   /storages                   저장소 생성 (owner 자동 등록)
  GET    /storages/{id}              저장소 상세 조회
  PUT    /storages/{id}              저장소 수정 (owner, editor)
  DELETE /storages/{id}              저장소 삭제 (소프트 삭제, owner만)

[스팟 - /storages/{storage_id}/spots]
  GET    /storages/{id}/spots        스팟 목록 (페이징: page, size)
  POST   /storages/{id}/spots        스팟 생성 (place_id 필수)
  GET    /storages/{id}/spots/{sid}  스팟 상세
  PUT    /storages/{id}/spots/{sid}  스팟 수정 (is_visited=True 시 visited_at 자동 기록)
  DELETE /storages/{id}/spots/{sid}  스팟 삭제 (소프트 삭제)

[창고 멤버 - /storages/{storage_id}/members]
  GET    /storages/{id}/members          멤버 목록 (멤버 누구나, nickname/profile_image 포함)
  POST   /storages/{id}/members          user_id로 멤버 추가 (owner, editor|viewer만)
  PATCH  /storages/{id}/members/{uid}    role 변경 (owner. role="owner"면 기존 owner→editor 자동 강등 atomic)
  DELETE /storages/{id}/members/{uid}    멤버 추방 (owner. 본인 추방은 400, /me 안내)
  DELETE /storages/{id}/members/me       self-leave (모든 멤버. owner는 400 거부)

[장소 - /places]
  GET  /places?q=검색어              장소 검색 (이름 기반, 페이징)
  GET  /places/{id}                  장소 상세 조회
  GET  /places/{id}/space-dna        장소 공간 DNA 조회 (없으면 has_data=false)

[인스타그램 - /instagram]
  POST /instagram/crawl         URL 크롤링 (OG 메타, 동기 - 레거시 유지)
  POST /instagram/crawl-async   Apify 기반 크롤링 (비동기 큐, 캐시 hit 시 즉시 반환)
  GET  /instagram/jobs/{id}     비동기 잡 상태/결과 조회
  POST /instagram/share         자동 매핑 + 저장 (캡션 → 후보 추출 → 네이버 검색 → 유니크 1건이면 자동 저장, 그 외 후보 반환)
  POST /instagram/save          크롤링 + 저장 (Place -> PlaceRawData -> PlaceImage -> Spot, 수동 폴백 경로 포함)

[헬스체크 - /health]
  GET  /health/db            DB 연결 상태 확인


5. 주요 구현 특징
------------------------------------------------------------
- JWT 인증: OAuth2PasswordBearer + Swagger Authorize 버튼 정상 동작
- 권한 관리: StorageMember 기반 role 검사 (owner/editor/viewer)
- Instagram 크롤링: Playwright + BeautifulSoup OG 메타 파싱
  - URL 검증 (instagram.com 여부)
  - 비공개/삭제 게시물 감지 (OG 메타 비어있으면 404)
  - 타임아웃/차단 처리 (504)
- 페이징: GET /storages, GET /spots에 page/size 쿼리 파라미터
- 소프트 삭제: deleted_at 필드 활용, 목록 조회 시 자동 필터

[2026-05-11 — 지도 핀 표시용 엔드포인트 (GET /users/me/pins)]
- 배경: 클라이언트가 네이버 지도 위에 사용자 저장 spot을 핀으로 표시할
  지도 화면이 필요. 기존 GET /storages/{id}/spots는 좌표 미포함 →
  spot마다 GET /places/{id}를 따로 부르면 N+1. 지도 전용 슬림 응답이 필요.
- 신규
  - app/schemas/pin.py: PinResponse(spot_id, storage_id, place_id, name,
    latitude, longitude, is_visited, thumbnail_url)
  - app/routers/users.py에 list_my_pins 핸들러 + _parse_csv_ints/_parse_bbox 헬퍼
  - scripts/_oneoff_check_pins_query.py: PostGIS dry-run (GIST 인덱스 + ST_X/Y/MakeEnvelope)
  - scripts/_oneoff_check_pins.py: 핸들러 직접 호출 검증 (8 케이스)
  - scripts/_oneoff_check_pins_data.py: DB 데이터 진단 (사용자/창고별 spot 분포)
- 변경 없음: 모델/마이그레이션/기존 라우터/app/main.py (users 라우터 이미 등록됨)
- 엔드포인트 명세
  - GET /users/me/pins?storage_ids=1,3,5&visited=true|false&bbox=swLng,swLat,neLng,neLat
  - 다중 storage 합치기 / viewport bbox / visited 필터 모두 한 엔드포인트
  - 응답 1001건까지 받아 truncation 감지 → X-Truncated: true 헤더
  - 비멤버 storage_id 1개라도 있으면 404 + inaccessible_ids
- 정책 결정 (3중 검증)
  - silent drop 대신 404: /storages/{id} 패턴 일관성, 디버깅 명시성
  - 좌표 추출은 SQL ST_X/ST_Y로 raw row 매핑 (PlaceResponse computed_field
    + to_shape는 1000건 시 ORM 메모리 비효율)
  - 핀 클릭 시 인스타 출처는 lazy 로딩 (기존 GET /storages/{id}/spots/{sid} 재사용)
  - bbox 필터는 GIST 인덱스가 자동 사용되므로 zero-cost 안전망
  - 좌표 없는 spot은 응답 제외 (지도에 못 박으니 불필요)
- 운영 Supabase 검증 (읽기만)
  - dry-run: GIST idx_places_coordinate 존재 + ST_X/Y/MakeEnvelope 정상 동작
  - 단일 창고(user 13/storage 13): 21건 정상 반환
  - 다중 창고(user 23/storage 26+27): 3건(2+1) 합쳐서 반환
  - bbox 필터: 한국 전체=21건 / 좁은 영역=0건
  - 비멤버 storage 99999999: 404 + inaccessible_ids
  - 부분 비멤버(26+99999999): 26 데이터 누설 없이 404
  - 형식 오류: storage_ids=abc → 422, bbox=1,2,3 → 422
- 미수행: truncation 케이스(1001건)는 운영 DB 시드 필요로 스킵
